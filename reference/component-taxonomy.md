# Component Taxonomy

## Question

How are component concepts classified?

## Purpose

This document provides canonical lookup categories for component concepts in UI Foundations.

## Classes

- Component: reusable UI building block with a distinct responsibility and stable public model.
- Component responsibility: the specific purpose a component owns.
- Component boundary: the line between local composition, pattern guidance, and component ownership.
- Component composition: the internal or external arrangement of parts needed to preserve meaning.
- Component state: temporary condition, interaction, or availability within a component.
- Component status: semantic meaning expressed by a component or its content.
- Component lifecycle: the maturity path from recurring need to stable system unit or retirement.
- Component surface: the public area where a component is understood, selected, configured, or reviewed.
