# Terminology

## Question

What terms are canonical in UI Foundations?

## Purpose

This document defines shared vocabulary for the vault. Definitions are concise lookup entries, not design guidance.

## Terms

- Architecture: the conceptual structure that explains how knowledge, decisions, and system parts relate.
- Artifact: a produced asset or document resulting from work.
- Capability: a reusable definition of what can be done, independent of who or what executes it.
- Canonical source: the single authoritative reference for a specific piece of knowledge or definition.
- Component: a reusable UI building block with a distinct responsibility and stable public model.
- Context: transient information assembled for a specific review, decision, or action.
- Core token: a primitive token that provides raw reusable material without product or component meaning.
- Decision: a recorded conclusion about a course of action or design choice.
- Design intelligence: contextual judgment beyond rule compliance.
- Evaluation: assessment of quality, effectiveness, or fit against defined knowledge.
- Foundation: immutable design knowledge that remains valid independent of UI Foundations implementation.
- Governance: rules for how vault knowledge is reviewed, trusted, changed, and retired.
- Knowledge: validated information used to support decisions or actions.
- Mode: contextual variation such as appearance, density, contrast, or environment.
- Operational knowledge: playbook-style knowledge for applying existing source knowledge.
- Pattern: reusable composition intent for a recurring interface problem.
- Reasoning: deriving conclusions from goals, constraints, evidence, assumptions, and source knowledge.
- Repository boundary: the responsibility line between ecosystem repositories.
- Review: evaluation of work or knowledge against relevant standards, specifications, and evidence.
- Runtime: the repository or system layer that provides executable assets.
- Semantic token: a token that exposes stable design meaning.
- Specification: a document that defines requirements, constraints, structures, or expected behavior.
- Studio: the workspace layer for interacting with the UI Foundations ecosystem.
- Synthesis: combining multiple findings into a coherent interpretation.
- State: a temporary condition, interaction, or availability within a component.
- Status: global semantic meaning such as severity, success, or warning.
- Theme: brand-level interpretation of shared semantic structure.
- Token: a named design decision that can be referenced by higher-level knowledge.
- Verification: checking whether a claim, recommendation, or artifact is supported by evidence.
- Workflow: a repeatable sequence of steps that produces an output.
