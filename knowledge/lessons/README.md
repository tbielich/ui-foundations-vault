# Lessons

Lessons are extracted from concrete work and written so they can be reviewed, cited, and promoted.

## Lesson Shape

A lesson should include:

- Source issue, PR, experiment, review, or incident.
- Local fact observed.
- Generalized lesson.
- Affected repositories or domains.
- Proposed next action.
- Promotion candidate, if any.

## Current Lessons

- `agentic-repository-scan.md`: cross-repository agentic architecture scan and promotion candidates.
- `uilib-consumer-capability-projection.md`: consumer-native projection shapes from UILib proof of use.
- `uilib-generated-projection-materialization.md`: deterministic, disposable projection materialization from canonical sources.
- `uilib-projection-preflight.md`: preflight-before-mutation and last-valid-output preservation.
- `uilib-projection-delivery-semantics.md`: live service versus snapshot artifact delivery semantics.

## Promotion

Repeated lessons should be proposed as governance, specification, workflow, prompt, or export-pack updates.

External proof-of-use systems may support promotion, but they do not acquire UIF authority through observation alone. Promote only generalized meaning that is compatible with UIF scope and existing higher-authority sources.
