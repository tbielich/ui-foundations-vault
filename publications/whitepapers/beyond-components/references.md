# References

All web references were accessed on 2026-07-16. Maturity labels are included where they materially affect interpretation.

<a id="ref-dtcg-format"></a>

## Design Tokens Community Group. *Design Tokens Format Module 2025.10*

Community Group Final Report, 28 October 2025. Defines a vendor-neutral JSON interchange format for design-token data. <https://www.w3.org/community/reports/design-tokens/CG-FINAL-format-20251028/>

<a id="ref-dtcg-reports"></a>

## Design Tokens Community Group. *Technical Reports*

Report index distinguishing stable, draft, and experimental publications. <https://www.designtokens.org/technical-reports/>

<a id="ref-w3c-dtcg"></a>

## World Wide Web Consortium. *Design Tokens Community Group*

Community Group description and participation information. Community Group outputs do not automatically represent W3C Member consensus. <https://www.w3.org/groups/cg/design-tokens>

<a id="ref-wcag22"></a>

## World Wide Web Consortium. *Web Content Accessibility Guidelines (WCAG) 2.2*

W3C Recommendation, 12 December 2024. <https://www.w3.org/TR/WCAG22/>

<a id="ref-wai-apg"></a>

## W3C Web Accessibility Initiative. *ARIA Authoring Practices Guide: Introduction*

Informative guidance explaining accessible UI patterns, keyboard interaction, and semantics, and distinguishing APG guidance from normative WCAG and ARIA standards. <https://www.w3.org/WAI/ARIA/apg/about/introduction/>

<a id="ref-google-design-md"></a>

## Google Labs Code. *DESIGN.md Format*

Alpha specification for a plain-text design-system representation combining YAML token data and markdown guidance. <https://github.com/google-labs-code/design.md/blob/main/docs/spec.md>

<a id="ref-figma-code-connect"></a>

## Sjölander, Emil. *The Right Code for Your Design System*

Figma, 16 April 2024. Introduces Code Connect as a maintained mapping between design components, production code, and contextual documentation. <https://www.figma.com/blog/introducing-code-connect/>

<a id="ref-github-accessibility-journey"></a>

## Mounter, Diana. *Design's Journey Towards Accessibility*

GitHub Engineering, 17 May 2023. Describes Primer's evolution through CSS, components, primitives, tokens, and accessibility work. <https://github.blog/engineering/user-experience/designs-journey-towards-accessibility/>

<a id="ref-github-inclusive-components"></a>

## Bailey, Eric. *How We're Building More Inclusive and Accessible Components at GitHub*

GitHub Engineering, 7 May 2024; updated 24 November 2025. Describes collaborative development and adoption of shared accessible list and table components. <https://github.blog/engineering/user-experience/how-were-building-more-inclusive-and-accessible-components-at-github/>

<a id="ref-github-annotations"></a>

## Maarten, Jan. *Design System Annotations, Part 1: How Accessibility Gets Left Out of Components*

GitHub Engineering, 9 May 2025; updated 24 November 2025. Examines contextual accessibility information that component assets do not encode by themselves. <https://github.blog/engineering/user-experience/design-system-annotations-part-1-how-accessibility-gets-left-out-of-components/>

<a id="ref-github-agents-md"></a>

## GitHub. *Copilot Coding Agent Now Supports AGENTS.md Custom Instructions*

GitHub Changelog, 28 August 2025. Documents repository-level and nested persistent instructions for coding agents. <https://github.blog/changelog/2025-08-28-copilot-coding-agent-now-supports-agents-md-custom-instructions/>

<a id="ref-fluent-tokens"></a>

## Microsoft. *Design Tokens — Fluent 2 Design System*

Defines Fluent's global and alias token layers and their role across platforms and disciplines. <https://fluent2.microsoft.design/design-tokens>

<a id="ref-microsoft-content-engineering"></a>

## Microsoft. *Content Engineering — Fluent 2 Design System*

Guidance on system prompts as shared design artifacts structured through roles, tasks, rules, and examples. <https://fluent2.microsoft.design/content-engineering>

<a id="ref-anthropic-agents"></a>

## Anthropic. *Building Effective Agents*

Anthropic Engineering, 19 December 2024. Distinguishes workflows from agents and recommends simple, composable agentic patterns. <https://www.anthropic.com/engineering/building-effective-agents>

<a id="ref-anthropic-context"></a>

## Anthropic. *Effective Context Engineering for AI Agents*

Anthropic Engineering, 29 September 2025. Describes context selection, attention constraints, retrieval, and tool clarity for agents. <https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents>

<a id="ref-anthropic-evals"></a>

## Anthropic. *Demystifying Evals for AI Agents*

Anthropic Engineering, 9 January 2026. Describes code-based, model-based, and human evaluation approaches for multi-turn agents. <https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents>

<a id="ref-spectrum-tokens"></a>

## Adobe. *Design Tokens — Spectrum*

Explains Spectrum's global, alias, and component-specific token model and the limits of tokens as a complete knowledge source. <https://spectrum.adobe.com/page/design-tokens/>

<a id="ref-spectrum-principles"></a>

## Adobe. *Principles — Spectrum*

Describes Spectrum's research, accessibility, transparency, versioning, and community principles. <https://spectrum.adobe.com/page/principles/>

<a id="ref-adobe-design-data"></a>

## Adobe. *Design Data Specification*

Version 1.0.0-draft. Draft specification for machine-readable tokens, components, registries, accessibility vocabulary, document blocks, lifecycle, and agent-readable operations. <https://opensource.adobe.com/spectrum-design-data/spec/>

<a id="ref-carbon-overview"></a>

## IBM. *What Is Carbon?*

Overview of Carbon as IBM's open-source system of styles, components, and guidelines. <https://carbondesignsystem.com/all-about-carbon/what-is-carbon/>

<a id="ref-carbon-contributing"></a>

## IBM. *Contributing to Carbon: Getting Started*

Defines contribution categories and phased treatment of new components and enhancements. <https://carbondesignsystem.com/contributing/get-started/overview/>

<a id="ref-shopify-polaris"></a>

## Shopify. *Polaris References*

Describes Polaris as Shopify's unified UI framework across application surfaces. <https://shopify.dev/docs/api/polaris/index>

<a id="ref-polaris-tokens"></a>

## Shopify. *Color Tokens — Polaris*

Documents semantic color-token structure, intent, state modifiers, and design-to-code usage. <https://polaris-react.shopify.com/design/colors/color-tokens>

<a id="ref-nng-consistency"></a>

## Nielsen Norman Group. *Consistency and Standards: Usability Heuristic 4*

Explains internal and external consistency and the relationship between design systems and user learning. <https://www.nngroup.com/articles/consistency-and-standards/>

## Fowler, Martin. *Architecture Decision Record*

24 March 2026. Describes short, version-controlled records for decisions, context, consequences, status, and supersession. <https://martinfowler.com/bliki/ArchitectureDecisionRecord.html>

## Dehghani, Zhamak et al. *Governing Data Products Using Fitness Functions*

MartinFowler.com, 18 September 2024. Applies architectural fitness functions to continuous, rule-based governance. <https://martinfowler.com/articles/fitness-functions-data-products.html>

<a id="ref-fowler-evolutionary"></a>

## Fowler, Martin. *Foreword to Building Evolutionary Architectures*

5 October 2017. Describes architecture as continuous work that responds to changing requirements and implementation feedback. <https://martinfowler.com/articles/evo-arch-forward.html>
